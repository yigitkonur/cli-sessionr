Kiro targeted resume follows the REFUSE path because this environment has no local kiro-cli binary to verify support for session-ID targeting, and the existing resume hint already documented that Kiro resumes only the most recent cwd session rather than a specific ID. To avoid silently sending a prompt to the wrong session, buildResumeCommand('kiro', ...) now raises UNSUPPORTED_OPERATION with the new-session suggestion, and getResumeHint('kiro', ...) advertises only starting a new Kiro session until runtime verification proves targeted resume support.
